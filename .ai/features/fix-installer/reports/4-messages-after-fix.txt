
######## Item 4: DNS advice behind NAT (the domain already points somewhere, the server goes out from another address)
Step 3 of 12: Checking that community.example.test points at this server

community.example.test doesn't point at this server yet.

Log in to the company where you bought your domain, open its DNS settings and create this record:

  Type:   A
  Name:   community
  Value:  203.0.113.20

If community.example.test is your main domain, with nothing in front of it, use @ as the name.

This server goes out to the internet from 203.0.113.20, but none of its own network cards has that address.
It may sit behind NAT or a load balancer (as on Fly.io), where visitors reach it on another address.
Right now community.example.test points at 2001:db8::99. If that's where visitors reach this server, the record is right.
Keep it instead of creating the one above, and run the command again with that address:

  curl -fsSL https://raw.githubusercontent.com/VillageHQ/community/main/install.sh | sudo COMMUNITY_DOMAIN=community.example.test COMMUNITY_SERVER_IP=2001:db8::99 bash

If not, change or delete the record that points at 2001:db8::99, and create the one above.
On Cloudflare, set the record to "DNS only" (the grey cloud).
Changes usually show up within a few minutes, and sometimes take up to an hour.

Create that record, wait a few minutes, then run the same command again.
